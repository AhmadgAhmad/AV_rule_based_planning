WINDOWS CARLA

Memory Flush — No Restart Needed

Debug Guide
Flush CARLA Memory
Between Sessions
CARLA on Windows leaves zombie CarlaUE4.exe processes after two runs that hold GPU memory and port 2000. No restart required — just kill them correctly.

⚠ Root Cause

When a Python script ends (or crashes) without destroying actors and properly disconnecting, the Unreal Engine 4 server process keeps running in the background. It holds onto VRAM and binds port 2000, so the next CARLA launch silently fails or behaves incorrectly. The /T flag when killing processes is critical — it kills all child threads, not just the parent.

1

Kill CARLA Processes

Run these two commands in any Command Prompt or PowerShell window. The /T flag kills child threads. The 2>nul suppresses errors if CARLA isn't running.
Command Prompt / PowerShell
BATCH 
taskkill /F /IM CarlaUE4.exe /T
taskkill /F /IM CarlaUE4-Win64-Shipping.exe /T
Wait 3–5 seconds after running these before launching CARLA again. The GPU needs a moment to finish releasing VRAM.
2

Release Port 2000 (if still bound)

If CARLA still can't start, something is still holding port 2000. Find the PID and kill it.
Find and kill whatever is holding port 2000
BATCH 
# Step 1: find the PID holding port 2000
netstat -ano | findstr :2000

# Step 2: kill it (replace 1234 with the PID from above)
taskkill /PID 1234 /F
3

Check GPU Memory (NVIDIA)

Verify VRAM has been freed after killing the process. Look for Used MiB in the output — it should drop significantly.
Check GPU memory usage
BATCH 
nvidia-smi

# If VRAM is still full after killing the process, force a reset:
nvidia-smi --gpu-reset
4

One-Click Cleanup Script

Save this as carla_cleanup.bat on your desktop. Double-click it between CARLA sessions — it handles everything automatically.
carla_cleanup.bat
BATCH 
@echo off
echo Killing CARLA processes...
taskkill /F /IM CarlaUE4.exe /T                           2>nul
taskkill /F /IM CarlaUE4-Win64-Shipping.exe /T            2>nul
taskkill /F /IM python.exe /T                             2>nul

echo Releasing port 2000 and 2001...
for /f "tokens=5" %%a in ('netstat -ano ^| findstr :2000') do taskkill /PID %%a /F 2>nul
for /f "tokens=5" %%a in ('netstat -ano ^| findstr :2001') do taskkill /PID %%a /F 2>nul

echo Flushing DNS...
ipconfig /flushdns

echo
echo Done. Waiting 5 seconds before you relaunch CARLA...
timeout /t 5
5

Permanent Fix — Python Cleanup

The real fix is preventing zombie processes in the first place. Add this to the top of every scenario script so it kills any leftover CARLA process before connecting.
Add to top of any scenario script
PYTHON 
import subprocess, time, sys

def flush_carla():
    """Kill any leftover CARLA process before connecting."""
    if sys.platform != 'win32':
        return

    procs = ['CarlaUE4.exe', 'CarlaUE4-Win64-Shipping.exe']
    for proc in procs:
        subprocess.call(
            ['taskkill', '/F', '/IM', proc, '/T'],
            stdout=subprocess.DEVNULL,
            stderr=subprocess.DEVNULL
        )

    time.sleep(3)   # wait for GPU to release VRAM
    print("[init] CARLA flushed — safe to connect.")


# Call this at the top of run() before client = carla.Client(...)
flush_carla()
Why it crashes after exactly two runs: the first run leaves a zombie process. The second run spawns on top of it (barely works). By run three, there are two zombies fighting over port 2000 and the remaining VRAM.
Also make sure every scenario script has a finally block — this is already in the scenario scripts from this session:
Every scenario run() function
PYTHON 
try:
    # ... scenario code ...

finally:
    # Always runs — even if an exception crashes the script
    for actor in actors.values():
        if actor and actor.is_alive:
            actor.destroy()         # frees server-side memory

    settings.synchronous_mode = False
    world.apply_settings(settings) # restore async mode
    print("[cleanup] Done.")
With both in place — flush_carla() at the top and finally at the bottom — CARLA should run indefinitely without needing a restart or the batch script.
